# Rollout — five improvements (2026-10-13)

Branch `ccr-d176df5c-h3ui3e`. Five initiatives built on a shared foundation:

1. **Account page → one-screen pre-call brief** (real buyer + Call, Directions, Before you call)
2. **Speed & resilience** (instant shell, cache by nightly load, saved on the phone, installable app, offline read-only)
3. **"Worth a call today"** on the Overview, Accounts sort chips + My plan, real "Last active"
4. **AI you can trust + what to sell** (correct brief numbers, nightly batch targeting, tappable brief, reorders in stock, Who should I call?)
5. **"Where's my order?" in one tap** (Lookup lines + Send status, header search, Recent activity that says what shipped/slipped, faster lookups, no 5 PM freeze)

Everything degrades cleanly: on a database **without** tonight's migrations the
preview works, and the DB-backed pieces simply don't appear (no error cards).

## 1. Deploy order

### a. Vercel preview — nothing to do
The branch push builds a preview. The build ends with
`[bundle] … entry budget 43.5 kB: ok` (a postbuild check now fails the build if
the startup bundle grows past budget).

Preview builds pick up a new push on reload automatically; production builds
show a "A new version is ready · Refresh" bar instead and never reload on their own.

### b. Migrations — apply with the deployer, before testing the DB-backed parts
All 11 are additive and backward compatible with the app, edge functions and
MCP server that are live today (append-only view columns, unchanged function
signatures), so they are safe to apply to the shared project before merging.

```bash
python etl/deploy_migrations.py --dry-run
python etl/deploy_migrations.py
```

### c. Edge functions — when you're ready for them to go live
These deploys hit production immediately (shared project). They stay compatible
with the live frontend (the territory brief still writes its prose `content`).

```bash
# --no-verify-jwt as always (supabase/functions/README.md → Deploy)
supabase functions deploy ai-account-summary --no-verify-jwt
supabase functions deploy ai-brief           --no-verify-jwt
supabase functions deploy ai-summary-batch   --no-verify-jwt
supabase functions deploy mcp                --no-verify-jwt
```

Prompt versions bump (account 4.1.0, territory 2.1.0), so every cached brief
regenerates once. `ai-summary-batch` has a new optional env var
`AI_BATCH_TIME_BUDGET_SECONDS` (default 75).

### d. ETL box — after the migrations
Pull **`etl/push_to_supabase.py` and `etl/views.yml` together** (the new
`views.yml` uses `{sql, optional}` step entries the old loader can't read).
What changes nightly:
- new optional steps: `analyze_territory_rollups()`, `capture_order_changes()` — a failure is logged, never fails the night;
- the `etl:run` freshness stamp is logged **before** the AI batch, so the app's "data loaded" moment no longer waits on it;
- the AI batch runs as up to 8 small calls (`max_accounts: 15`, `repeat_until_idle: 8`) instead of one long one.

## 2. What to test on the preview

Use a rep login on a phone (or DevTools at 390px). Items marked **[mig]** need
the migrations; **[fn]** needs the edge function deploy.

### Account page
- Open a buying-group dealer whose ERP "primary" is an INVOICE/AP mailbox (the
  research sample: RED ROCK, CAPIT SPORT, CROWN ENT). The header names the
  **actual buyer** with a big **Call** button; billing desks are folded into
  "Billing & other contacts (n)" in the Contacts card.
- A dealer with no phone anywhere (e.g. MURD RAN1, GUIDEFITTER) says
  **"No buyer number on file"** with **Add contact**.
- **Directions** opens Google Maps (for chains this is head office).
- **Before you call**: ordering rhythm, last order (tap → its lines), still
  owed + next promise, pricing → Price Lists. **[mig]** "Bought before · in stock
  now" with **Due** badges.
- Flip **feature.orders** on (Admin → Settings): **New order** chip and **Add to
  order** buttons open the order writer pre-filled.
- `/accounts/<key>?order=<order id>` opens that order's lines (even old orders).
- Fewer requests on open (DevTools → Network): no `recommendations`, `notes`,
  `actions` while those flags are off; collapsed cards load when opened.

### Overview
- **Worth a call today** sits under the money tiles: reasons in plain English,
  ▲/▼ vs the same time last year, **Call** and **Directions**.
- **[mig]** "⋯" → On it / Already handled / Not relevant ▸ reason; the row leaves
  your list for 3 / 14 / 45 days with **Undo**.
- **[mig]** Admin → Settings → turn on **Quick call log**; tap Call, come back to
  the browser → "How did the call go?" → logs a call on the account.
- **Recent activity**: **[mig]** Shipped (Track, Send tracking), New orders,
  Heads-up (promise slipped), "N new since last look". Without the migration it
  shows the old orders list.
- **[mig][fn]** Sales Brief headlines get account chips; **"Was this useful?"** under it.

### Accounts
- Sort chips: A–Z, Biggest, Slipping, Longest since order, Behind goal; every
  card shows YTD ▲/▼ and one reason.
- ☆ a few accounts → **★ My plan (n)** → **Route these** opens a multi-stop route.

### Find / header search
- Header magnifier (or "/" on desktop): recent dealers before typing; Dealers,
  Orders (PO, order #, tracking — 3+ chars) and Products while typing.
- Find → **Show lines**, **Send status** (share sheet on a phone, "Copied" on a
  laptop), **Text <buyer>**, **Open in account**. Past-due promise dates are
  called out as late in the message.

### Sales Intel
- The tab formerly "ATS" is **In stock**: **Who should I call?** on every
  product; pick a dealer to toggle **New to them / Reorders**.
- SKU Sales labels last year honestly ("All of 2025") — no misleading % in October.

### Speed & offline
- Hard-reload `/`: the dark header and card outlines paint immediately.
- Reopen the app later: the Overview appears without skeletons (cached on the
  phone for reps; admins never cache).
- Install: Android "Install app" / iPhone Share → Add to Home Screen (new icon).
- Airplane mode, reopen from the home screen: **"You're offline — showing what
  was saved at …"**, read-only; reconnect and it clears by itself.
- Password-reset email link still works with the service worker installed.

### Admin
- Activity: **Last active** / **Sessions 30d** now count app opens (at most
  once per 4h per person, never while viewing as a rep).

### MCP (after `mcp` deploy)
- New `find_dealers_for_sku`; `list_contacts` returns the buyer first with a
  `best_contact`; prompts *Pre-call brief*, *Plan my week*, *What can I sell
  from today's stock*.

## 3. Known limits and deferred work

- Account open is 17 requests cold (was 20), not the ~8 hoped for — the rest
  needs a combined `account_page` RPC.
- Offline: pages never opened online show skeletons; contacts/goal/AI summary
  on the account page aren't saved for offline.
- Admin same-day changes (reassignments) can take up to ~3h to reach a rep's
  cached views; ETL loads are picked up immediately via the freshness heartbeat.
- The call list's "No answer" outcome counts as contact coverage.
- Reorder list membership can still change the AI hash when stock crosses zero.
- Deferred by design: batch territory briefs (needs an identity decision),
  auto-closing stale recommendations, season-aware cadence, rule-effectiveness
  analytics, intraday loads, atomic multi-table ETL swap, email digests.

Local validation at push time: frontend build + bundle budget, 23 unit-test
files, the SQL suite on a fresh Postgres 16 (all new tests pass; the three
pre-existing failures are unchanged: `rollup_restore` data check on an empty
DB, stale `036_sku_gaps`, harness grants for help T4), `deno check` on all six
functions + 35 deno tests, ETL loader tests, and a mocked-Supabase browser
smoke run of every route as rep / admin / order-entry with flags on and off and
with every new DB object missing.
